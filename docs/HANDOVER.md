## 3. 核心规则（以代码为准，别凭印象）

**时间**：`WEEKS_PER_TERM = 20`、6 学期 = **120 周**，定义在 `js/09-data-fixed.js`。
寒暑假是独立阶段**不占周数**：第 20 周结束 → 假期（`S.vac`）→ `S.term++` → 周数接着数（第 21 周）。假期顶栏显示「❄️ 寒假 / 🌞 暑假」，不出现「第 N 周」。
开学弹窗**不占周**（`S.fixedDone` 标记）。

**属性**：面板可见 4 项 —— 心态 / 经济 / 健康 / 压力。除经济外都是五档文字（极低/较低/中/较高/极高），不显示数值。效率、悟性、社交、亲情后台实时算但隐藏。学科分数只在考试事件出现。

**中考 530 分三段**：
1. 初二下期末「生地会考」→ 生物地理成绩锁死；
2. 实验操作（生物/物理/化学各 10 分，第一次认真做当场拿满，敷衍要补考并付代价）；
3. 初三下期末中考，合上锁死成绩按权重折：语数英 ×100%、物 ×50%、史政 ×40%、生 ×40%、地化 ×30%。

语文 87 分以上每涨 1 分需 2.5 倍学力（90 是坎，92 基本天花板）；生物/物理/化学卷面满分 90，剩 10 分在实验台。

**难度**：默认 `hard` + `planId: "full"`。三档系数在 `GAME_CONFIG.difficultyTune`，由 `studyCfg()` 乘到基础旋钮上（剧情 ×1.10/0.75/1.06/0.70，标准全 1.00，硬核 0.82/1.45/0.90/1.35）。

**主题**：9 套。`siji`（四季）是特例 —— 由 `seasonPhase()` 按「校历月份 + 当月第几周」连续插值四套 `SEASON_PALETTES`，背景四层按比重交叉淡入，`renderHUD()` 每次调 `refreshSeason()`。

**存档**：`SAVE_VER = 7`，3 个槽，每周结算后自动存一次；读档有脏数据过滤（数组、缺字段、负数、类型错都会被拦掉）。

**文档**：弹窗只有「关闭」一个按钮，来源标注只有「来自 docs 目录（实时）」和「当前版本」。本地导入已停用，启动时 `dropDocCache()` 清掉旧缓存。

## 5. 踩过的坑全集（经验库）

每条格式：**现象 → 根因 → 修法**。这些都是"看起来没问题、一跑就出事"的类型。

**1｜弹窗上下冗长、多出大量空行**
模板字符串为了好看的缩进换行，被 `white-space: pre-wrap` 渲染成真实空行（新手介绍 4221px → 2341px）。改成默认 `normal`，只有需要保留换行的地方单独声明。

**2｜界面出现一整串 `style="--c1:#8a2b9c..."` 可见代码**
`\n → <br>` 无差别替换，把 HTML 标签内部的换行也转了，标签结构被破坏、属性泄漏成正文。修法：`nl2br()` 逐字符扫描、跟踪是否在 `<...>` 内，只转「夹在真实文字之间」的换行。

**3｜档位文字「中/较高」看不见**
CSS 里 `color` 和 `background` 写成同一个值，等于红字画在红方块上。文字只留颜色、去掉底色，刻度填充单独画在格子上。

**4｜按钮点一下状态变了、文字不动**
重渲染用 `cloneNode` 换掉按钮，闭包里存的是旧节点。`apply()` 里必须每次重新 `getElementById` 取值。

**5｜开学白吃掉一整周**
开学弹窗关闭直接跳下一周。用 `S.fixedDone` 标记，开学不占周。

**6｜「初三的学长」永远修不好**
按年级切换写成了对象字面量里的三元表达式，**文件加载时就求值**，那时 `S` 还不存在，永远走「学长」分支。修法：引擎 `defOf()` 加 `t` / `c` 函数支持（向后兼容字符串）。同理「高年级学生堵你」在初三不成立，加 `maxTerm: 3`。

**7｜压力三年后必爆 / 必归零**
周结算原来是纯随机漫步 `rnd(31)-15` 无回归，配上「连续三周爆表离场」等于掷骰子定生死。改成向学业基线回归（初一 25 → 初三 50）。

**8｜剧情模式永远吵不起来**
`storyFloorFamily = 35` 高于家庭矛盾触发线 30。改成 22。

**9｜判卷把 `1.0` 判成 `10`**
归一化时把 `.` 当句号删掉，`0.5` 变 `05`。改成只删首尾与中文标点、保留数字中间的小数点。现在 `一/1/1.0/01`、`1/2/0.5/二分之一/50%`、`H₂O/h2o`、`4cm/4厘米` 都算对。

**10｜初三抽到生物地理、初一抽到物理**
`该科没有够格的题 → 退化成全部题库` 这条兜底会抽超纲题。去掉兜底，严格按 `subjectsOf` 过滤；体检脚本加「死题检测」（生物地理只考到初二，标了初三的题一辈子抽不到，曾查出 5 条）。

**11｜宿舍里出现手机**
学校对手机零容忍，抢社团却写在"宿舍里盯着手机报名"。改成在家。同类场景冲突要一起查。

**12｜乒乓球事件反复出现**
根因不是权重设错，是乒乓球社好进（约 60%）却只有 2 条事件。13 个社团统一补到 4 条。

**13｜人没去社团，故事却发生在社团教室**
选「不去社团」只走普通学习，但通用池仍可能抽到 `cond: S.club === "xxx"` 的事件。置 `S.clubOff`，抽取时跳过 `cl_` 开头事件。

**14｜旅游地图卡死**
「出发」按钮要求 `chosen.length !== need`（必须选满 2/3 站），钱只够一站时永远灰着。改成 `MIN_PICK = 1`，能走几站走几站，并提示「钱只够去 1 站了」。连带把 `minMoney` 从写死改成按「该线路最便宜一站」动态算（`cheapestOf()`），否则会出现"选了全国却一站都去不起"。

**15｜`need is not defined`**
把 `need` 改名 `want` 后漏改一处模板字符串，地图整个不渲染。改变量名后必须全局搜一遍。

**16｜编程社事件插入没生效**
脚本找 `],` 作为插入锚点，而最后一个社团块的结束是 `];`。批量脚本的锚点要覆盖两种写法。

**17｜`showPopup` 里按钮禁用状态设不上**
先执行了 `afterRender` 才给按钮挂 id，回调里按 id 取不到元素。调回顺序。

**18｜界面显示「约 {0} 起」**

**19｜提示条/飘字互相盖住**

## 6. 标准作业流程

```
cd tools
node check-content.js        # ① 内容体检：事件指令、题库答案、天赋引用、节假日
```

改主题额外跑一次**卡片对比度**（正文 ≥8、描边 ≥3）。
改数值额外跑一次**极端值测试**（全 0 / 全 150 / 全负 / NaN / undefined，确认无 NaN 且结局判定有结果）。

## 追加 · B 批已完成（需求 1~7，2026-11-07）

新增 `js/18b-create.js`（创角独立页）、`js/03d-talent-pick.js`（新天赋/蜕变/额度互斥）、`css/06-create.css`；`SAVE_VER` 升到 **8**。完整决策清单见 `docs/REQUIREMENTS.md` §7.5「B 批实施记录」，这里只补**新踩的坑**：

**坑 31 · `S.week` 是全局周，不是本局周**
从中间学期开局时若仍把 `S.week` 初始化成 0，顶栏会显示「第 1 周」（初三下开局尤其荒谬），且 `difficultyCurve()` 会把短局全程顶在最难档。正确做法：`week = termFrom × 20`，`weekInTerm() = week % 20 + 1`。难度曲线相应改回按全局 120 周算。

**坑 32 · 黑名单词条有 91 处是单向的**
`TALENTS[x].inc` 里 A 写了 B、B 不一定写 A。做天赋互斥校验必须双向查（`talentsConflict()`），只查一边会漏。

**坑 33 · `sticky bottom:0` 救不了页尾按钮**
创角页很长，矮屏上「开始这一局」原本在 1129px。`position:sticky; bottom:0` **不会**把位于包含块末尾的元素"提前"拉进视口，实测无效。改用 `fixed` 才行。

**坑 34 · `fixed` 居中别用 `translateX(-50%)`**
创角页吸底条同时带 `.card`，而 `.card` 有 `fadeInUp` 入场动画；CSS 动画帧的 `transform` 优先级高于普通声明，会把 `translateX(-50%)` 冲成 `translateY(7px)`，按钮直接跑出视口右侧（实测 `left=1356 > 1024`，点不到）。改成 `left:0; right:0; margin:0 auto; width:min(96vw,1000px)`，并给这条加 `animation:none`。另外 fixed 元素别留 `margin-top`，会把元素往下推出视口。

**坑 35 · 生地会考成绩以前不进存档**
`S.hk` / `S.hkDone` / `S.exp` 原本只在内存里，读档就丢，中考会拿当前学力重新估算。v1.4 补进 `saveGame()` 与 `resumeGame()`。从 t4/t5 开局时还要用玩家手填的成绩预置这三个字段。

**坑 36 · 彩蛋名要忽略中间空白**
只 `trim()` 首尾的话，「夏 IF」「夏　if」「xia yi fu」都能绕过去。改成剔掉所有 `\s`、全角空格 `\u3000`、零宽字符后再比对。

## 5.8 v1.4 E 批新增（坑 55~62）

**坑 55 · 在事件选项里再开一个弹窗，事件链会断**
`showPopup(def, () => showEventResult(step))` 的 `onClose` 就是「下一条事件」。小游戏若自己盖一层弹窗，这个回调丢了，玩家下完棋就卡住。修法：`showModal` 把 `onClose` 存到 `modalMask._onClose`，`openGomoku()` 只在遮罩**确实可见**时读它（顶栏自由入口时遮罩是 hidden，读到旧值会误触发上一次的事件链），结果窗再原样传回去。**别用新遮罩盖在原弹窗上。**

**坑 56 · `showPopup` 不传 `meta.feedback` 会给纯面板弹一个空的「这一下的结果」**
音乐面板、时间表编辑这类纯编辑窗，点「关闭」不该有反馈。必须用 `showModal(..., {feedback:false})` 显式标掉，或者走 `showPopup` 时把字段带上。

**坑 57 · `rgba(255,255,255, calc(var(--tint) * .35))` 会让整条 background 失效**
部分浏览器不接受 `calc()` 当 alpha，解析失败后整个 `background` 声明被丢，卡片直接变透明。改成两个独立变量 `--tint-top` / `--tint-mid`，别在颜色里做算术。

**坑 58 · 后加载的 CSS 也会输给特异性**
`css/03-modal.css` 写的是 `header.topline{margin-bottom:8px}`（0,1,1），我在最后加载的 `10-layers.css` 里写 `.topline{margin-bottom:0}`（0,1,0）**照样被盖掉**。矮屏溢出查了半天才发现选择器不够重。改 CSS 前先 `getComputedStyle` 确认值真的变了。

**坑 59 · 矮屏给 `.log`/`.opts` 加 1px border 会实打实吃掉 flex 高度**
1024×640 顶栏折成两行，上下 padding 14px + 两处 border 4px + margin 8px，正好溢出 21px。矮屏改 `border:0` + `box-shadow: inset 0 0 0 1px ...`，视觉一样但不占布局；`header.topline` 的 padding 只留左右、margin 收 0。

**坑 60 · 分层叠白会把浅色主题的对比度吃下去**
风主题正文对比度 6.8、深海 7.7，都不达标。**不要提亮文字**（会发飘、失去主题气质），把 `--panel` 压暗一档、`--bg` 保持通透 —— 卡片沉下去、背景亮起来，层次反而更清楚。校验脚本 `tools/check-contrast.js` 已挂进 `check-content.js`，以后加主题自动算。

**坑 61 · 验证 `game.html` 收录 CSS 不能按文件名 grep**
`make-single.js` 内联 JS 时会写 `/* ==== 文件名 ==== */`，内联 CSS 时**没有注释**。所以 `grep '10-layers' game.html` 是 0 却不是漏打包，要按 CSS 里的独特类名（`tint-top` / `layer-inner` / `audio-track`）查。

## 5.9 条空 bug 补丁（坑 63）

**坑 63 · `--glow` / `--glow2` 是 rgb 三元组字符串，不是颜色值**
主题切换改造时把这三个变量改成了 `"169, 95, 198"` 这种形式（方便写 `rgba(var(--glow), .2)`），但有 10 处 CSS 没跟着改，仍写成 `background: var(--glow2, var(--gold))`。浏览器展开后得到 `background: 169, 95, 198` —— **无效声明，整条属性被丢弃**，填充条完全透明。

这正是「耐久条 / 读书进度条有时候会空」的根因，而且「有时候」四个字很准：
- `.bagbar.low > i {background: var(--red)}` 是有效颜色 → **只有耐久 ≤25% 时**才看得见红条；
- 平时满耐久、以及读书进度条，全都是空的；
- 真实模式下连数字都没有，所以玩家完全不知道进度到哪了。

同一批误用还波及：体力条 `.stambar > i`（体力低时才显红）、旅游地图的景点圆点 `.spot-dot i`、游戏说明「展开」按钮文字、消息列表 hover 描边、创角页选中态与输入框聚焦描边。

**统一修法**：`rgb(var(--glow2, 192, 138, 232))` / `rgb(var(--glow, 156, 77, 204))`，fallback 也写成三元组（写 hex 会在变量未定义时变成 `rgb(#c9a3e0)`，一样无效）。渐变里同理。

配套三件事：
1. `css/07-bag.css` 给条轨道加 `inset 0 0 0 1px var(--line)`，进度真为 0 时也看得出「这是一条」，不是渲染丢了；读书条另加 `.bagbar.book` 金色渐变，和耐久条一眼分开。
2. `bagEnsure()` 兜底补 `durMax` / `progMax` / `stamPer` / `stagesDone` —— 旧存档或事件手工塞进来的物品缺字段时，条会被算成 0%，看起来也是「空」。
3. `tools/check-content.js` 新增 `checkCssColorVars()`：扫 10 个 CSS 文件，凡 `var(--glow*)` 没包在 `rgb()`/`rgba()` 里就报错。已验证 40 处引用全部合法。

**排查这类问题的通用手法**：别只看 DOM 里 `style="width:60%"` 对不对，要 `getComputedStyle(i).backgroundImage` —— 本例 width 一直是对的，空的是填充色。

## 5.11 v1.4.2 补丁 · 主菜单五子棋（坑 66）

**现象**：主菜单点「摆一局五子棋」→「认输离场」→ 结果窗点「收好棋子」，弹窗永远关不掉。控制台 `Cannot read properties of null (reading 'prop')`。

**根因**：主菜单没有存档，`S === null`。`gmkFinish()` 的「收好棋子」里无条件 `modProp(k, r[k])`，一进去就抛异常；异常发生在 `showModal` 的 `o.fn(S)` 里，**后面的 `hideModalRaw()` / `onClose()` 全都没执行**，弹窗就留在屏幕上。

**第二个坑（更隐蔽）**：判断"是不是主菜单"**不能只看 `!!S`**。`toStart()` 只切屏幕 class、不清 `S` —— 玩家从游戏回主菜单后 `S` 仍是一份完整存档。若用 `!!S` 判断，纯玩棋局会照常 `modProp` / `count` / `checkAch`，**偷偷改掉玩家存档**。正确依据是 `gameScreen.classList.contains("hidden")`。

**处理**（`js/20-minigames.js`）：
- `gmkStandalone()` 按游戏屏可见性判定；纯玩时 `resume` 强制 null，绝不接事件链。
- 纯玩棋局：标题「♟️ 摆一局五子棋」、badge「♟️ 纯玩」、按钮「🏳️ 不下了」、说明写「随手摆一局，不记入任何存档」。

## 5.12 v1.4.3 补丁 · 整站卡顿（坑 67）

**现象**：电脑上整体很卡，越玩越卡，开弹窗和触发氛围特效时尤其明显。

**先测再改**，用 Playwright 的真实 rAF 帧间隔（`--disable-frame-rate-limit` 会污染数据，别加），基线：

| 场景 | 优化前 |
|---|---|
| 平静 | 60fps |
| 红雾 + 灰暗 | 33fps |
| 三种氛围特效同时 | **27fps** |
| 弹窗打开 | **26fps** |
| 日志累积 1500 条 | **13fps（p95 216ms）** |

**三个根因**

1. **氛围层拆成多个全屏合成层**。`05-mood.css` 旧版四种效果各占一个 `::before` / `::after`，还叠了 `mix-blend-mode: multiply` 和 `#hud` 上的 `filter: saturate / blur`。单个特效不卡（60fps），三个一起就掉到 27。逐项关掉都只能回到 30~36，说明是**层叠加 + 混合模式**本身贵，不是某个属性。
2. **常驻 `backdrop-filter: blur`**。顶栏 `blur(14px)`、弹窗 `blur(16px)`，背后又是多层渐变 + 呼吸光晕，浏览器每帧重新采样整屏 → 弹窗打开掉到 49。而且 `--panel` 本来就是不透明色，**blurring 的是被完全遮住的区域，纯属白费**。
3. **日志 DOM 无限增长 + 每条强制同步布局**。`say()` 每写一条就 `appendChild` 再立刻读 `el.scrollHeight`（强制 layout），玩到后期上千条就 13fps。

**改法**

- 氛围特效合成 **一个** 全屏层：四段渐变的 alpha 各由 `--mood-stress/dark/weak/broke` 控制（未触发的变量默认 0 → 该段全透明）。呼吸只动 `opacity`。删掉 `mix-blend-mode` 和所有内容 `filter`；"灰暗"改成一层淡冷灰、"发虚"改成边缘压暗，观感接近但不再每帧做滤镜卷积。
- 顶栏 / 弹窗去掉 `backdrop-filter`，底层垫不透明的 `var(--panel)`，**九套主题配色不变**，对比度自检 12 套全达标。
- `say()`：日志 DOM 上限 120 条；`S.logs` **只增不裁**（`fbBegin/fbCollect` 用数组长度当游标，裁了会让「这一下的结果」丢文本）；滚动合并到下一帧，一次操作连写十条也只布局一次。飘字同帧上限 12 条。
- `setHudHtml()` / `setText()` diff 缓存：`renderHUD()` 一次操作里可能被调好几次，内容没变就不写 DOM。实测 100 次 `renderHUD()` 共 21ms、DOM 变更 0 次；属性真变了才重建 1 次。`newGameAt` / `resumeGame` 会清缓存。
- 无限动画收敛：`goldPulse` / `rainbowFlow` 删除（动 text-shadow / background-position，每帧重绘，天赋面板可能常驻）；`titleGlow` 改成只动 opacity。只剩 `themeBreath` / `moodBreath` / `titleGlow` 三个 opacity 动画，都走合成层。`prefers-reduced-motion` 下全部为 `none`。

**优化后**：上述六个场景全部回到 **60fps**，p95 16.7ms。点击响应中位 9.7ms。

防复发：`tools/check-content.js` 的 `checkRenderPerf()` 查 backdrop-filter、mix-blend、日志上限、HUD diff、氛围层数、重绘型无限动画。

**通用教训**：`backdrop-filter` 用在不透明背景上是纯浪费；全屏特效层能合一层就别拆多个；`scrollHeight` 在任何逐条写入的循环里都是隐藏的强制布局；无限动画动 `text-shadow` / `background-position` 等于每帧重绘。测性能要用真实帧间隔，别信 headless 下解了 vsync 的虚高 FPS。

## 5.18 v1.5.1 · 图书三项修复（坑 79）

用户报了三个连在一起的问题：**书占了文具袋格子、同一个存档能有好几本一样的书、
读完的书没用了**。三个其实是同一处设计没分层造成的。

### 症状与根因

| 现象 | 根因 |
|---|---|
| 买书会把文具袋挤满 | `bagAdd()` / `bagCanBuy()` / `bagBuy()` / `bagEnsure()` 全都用 `b.items.length` 数件数，而书也在 `items` 里 |
| 旧档读进来书会凭空消失 | `bagEnsure()` 里 `if (b.items.length > b.cap) b.items = b.items.slice(0, b.cap)` —— **先截断再分类**，书排后面就被切掉 |
| 同一种书能买两本 | 没有任何去重；`finished` 锁（坑 51）只挡「同一本重复点」，挡不住「两本一样的书各读一遍」，天赋还是能刷两次 |
| 买重时钱白扣 | `bagBuy()` 先 `modProp("经济", -price)` 再 `bagAdd()`；`bagAdd` 被拒时钱已经没了 |
| 读完之后再点「读」没意义 | `bookRead()` 只会 `done = full && !it.finished`，复读仍扣时间、磨笔，却什么也不给 |

### 改法：书是「书架」，不是「装备」

新增三个不调 `bagEnsure()` 的辅助函数（**调用方必须先 `bagEnsure()`，否则会递归**）：

- `bagIsBook(it)` —— `cat === "book"` 或 `bookDef(def)` 都认，兼容旧档
- `bagCount()` —— **只数非书类**，所有容量判定统一换成它
- `bagBooks()` / `bagHasBook(defId)` —— 后者连 `S.bag.lent`（借出去还没还的）一起看

`bagEnsure()` 改成**先分拨、再截断**：非书类 `slice(0, cap)`，书单独 `concat` 回来；
同 `def` 只留一本，保留进度最高的（`finished` 优先）。顺手补 `it.finished` / `it.rereads`
兜底 —— 不升 `SAVE_VER`，因为这是可选字段，`bagEnsure()` 幂等补齐，旧版读到会直接忽略。

所有入口都走同一套：`bagAdd()` 拒重、`bagCanBuy()` 置灰、`bagBuyFailWhy()` 给原因、
图书角只摆书架里没有的书、事件指令「文具 借书」从剩余池里挑、借出的书归还时先查重。
面板把书单列成「📚 书架（不占格子，读完可复读）」一段，件数头只显示 `bagCount()/cap`。

### 复读

`bookRead()` 在**时间校验之后、扣时间之前**分流：`if (it.finished) {bookReread(...); return;}`。
放进最前面会绕过 `canAfford()`，这个顺序别调。

`bookReread()`：耗时间、磨笔、磨袋身，从 `BOOK_REREAD` 六条里按 `rereads` 轮换一条
（`悟性 +3` / `心态 +3, 压力 -3` / `社交 +4` 等），**不推进进度、不触发 stages、
不抽天赋、不 `count("read")`**。翻过一整轮之后只给心态 +1，避免复读变成稳定属性来源。

两个细节：
- 结果窗标 `feedback:false`，属性变化交给 `modProp` 的飘字 —— 真实模式只飘 ▲▼，
  不会漏出「悟性 +3」（坑 75）。复读档位文案用「翻一小会儿 / 翻半下午 / 从头再翻一遍」，
  **不写点数**，真实模式选项上也没有具体数值。
- `bagReadUi()` 里已读完改叫「🔁 复读」，条目上加「不占格子」「已读完 · 可复读」两个 tag。

### 顺带修的

`bagBuy()` 改成**先 `bagAdd()` 成功、再扣钱**。这是买重被拒时静默吞钱的真 bug，
和产品需求无关，但正好被这次的去重暴露出来。

### 验收

`verify_book.js`：非书填满 cap 后仍能买书且件数不变、二次 `bagAdd` / 买重 / 事件指定塞同一本全被拒、
旧档手工塞 3 本重复书后净化成 1 本且保留进度最高那本、读满后复读不刷天赋不刷计数、
game/real 两档面板书架分区与复读档位、双入口 349 条文案零代码块、零报错。
`tools/check-content.js` 的 `checkBookRules()` 守以上全部规则。

## 5.20 v1.5.3 · 文具袋容量、图标、货架（坑 81）

### ① 容量口径：从「书不占」收紧到「只有笔和橡皮占」

v1.5.1 的 `bagCount()` 是「非书类都算」，所以球拍、书签、计算器、文具袋本身照样挤占 6 个格子。
这版改成 `bagOccupies(x)`：只有 `cat === "write" || cat === "eraser"` 为真。

要同步改**七处**，漏一处就会出现「买了书把笔袋挤满」或「笔袋满了还扣钱」：

`bagCount()` / `bagEnsure()` 的截断 / `bagAdd()` 的容量判定 / `bagCanBuy()` /
`bagBuyFailWhy()` / `bagBuy()` / 面板头部件数。

`bagEnsure()` 的截断顺序仍是 **先分拨、后截断**，顺序反了不占格子的东西会被 `slice(0, cap)` 切掉：

```js
const occupying = [], free = [];
...
b.items = occupying.slice(0, b.cap).concat(free);
```

**不占格子 ≠ 可以无限囤**。加了 `bagHasDurable()`（`sport`/`lab`/`charm` 同类只留一件），
并把 `bagWeeklyTick()` 改成按 `def` 去重累加 `weekly`/`perk` —— 否则买十个计算器就能每周白刷学力。
事件用 `force:true` 发奖励、旧档归还借出的书，都绕过这条限制。

### ② 两个图标

定义表原来把 emoji 写在名字里（`n:"✏️ 中华铅笔"`），面板又单独画一个 `.bag-ico`，
于是同一件文具出现两个 ✏️。**修法是把 `n` 改成纯文字，`icon` 单独留着**，
所有 `${d.icon} ${d.n}` 的拼接自动就只剩一个图标。

只改定义表不够 —— **旧存档把带 emoji 的 `n` 存进了 `S.bag.items`**。
所以在 `bagEnsure()` 里加 `if (d && d.n) it.n = d.n;`（`d.icon` 同理），读档时幂等覆盖。
不升 `SAVE_VER`：这是显示层字段，`bagEnsure()` 每次都会补。

> 体检脚本第一版用 `/n:"..."` 查名字里的 emoji，结果把 **`icon:"` 里的 `n:"`** 也匹配了，

## 5.21 v1.5.4 · 五子棋棋盘正方形（坑 82）

用户要求「下五子棋界面应保持正方形，无论什么屏幕」。查下来是**两个叠在一起的原因**，只改一个不够。

### ① `max-height` 把高度单独压掉

`css/08-minigames.css` 原来写的是：

```css
#gmkCanvas { width:min(416px,72vw); height:auto; max-height:52vh; }
@media(max-height:700px){ #gmkCanvas{max-height:40vh} }
```

canvas 的 intrinsic 是 416×416，`height:auto` 本该算出 1:1；但 `max-height` 会**只钳高度、不动宽度**。
1024×640 上宽度仍是 270，高度被压到 256 → 270×256 的扁矩形，格子和棋子都变形。

**修法**：把高度上限折算进边长本身，宽高都取同一个 `--gmk-side`，彻底删掉 `max-height`：

```css
.gmk-wrap { --gmk-side: min(416px, 72vw, 46vh); width: var(--gmk-side); }
#gmkCanvas { width:100%; height:var(--gmk-side); aspect-ratio:1/1; box-sizing:border-box; }
```

矮屏只改系数（`38vh` / `32vh`），并给下限 `max(180px,…)` / `max(160px,…)` —— 否则横屏 812×375
会小到 120px，13 路格子只有 8px，正方形是正方形了却点不动。外层再套 `min(92vw,…)` 防极窄视口横溢。

### ② `gmkFit()` 在入场动画里量错了尺寸

加了 JS 动态兜底后，第一版用 `getBoundingClientRect()` 读尺寸。弹窗有 `animation: pop .3s`
（`transform: scale(.85)→1`），**动画期间 rect 是缩放后的值**，写进内联 px 后棋盘永久小一圈：
1366×768 本该 353px 只剩 255px，横屏更是 92px。

**改用 `clientWidth` / `clientHeight`** —— 布局尺寸，不受 transform 影响。每次先清内联 px
让 CSS 按当前视口重算，再取 `min(w,h)` 同时赋给两边；`window.resize` 和 `visualViewport.resize` 都会重跑。

> 教训：**凡是要把量到的尺寸写回内联样式的，别用 `getBoundingClientRect()`**。
> 它含 transform / 缩放 / 滚动，测的是「屏幕上看到多大」，不是「布局给了多大」。

### ③ 顺带的界面处理

主菜单纯玩时，用 `.modal-mask.gmk-standalone .modal:has(#gmkCanvas) { width:fit-content }`
让弹窗贴着棋盘，整张卡片也是方的。`:has` 保证**结果窗没有 canvas 时不生效**，
否则一句收尾文案会被挤成一根窄条。不支持 `:has` 的浏览器只是留白多一点，棋盘仍正方形。

`gmkBind()` 末尾调 `gmkBindFit()` + `gmkFit()` + `gmkDraw()`；点击换算仍用
`cv.width/r.width`、`cv.height/r.height`，正方形下天然一致，实测点交叉点 (3,4) 落在 `GMK.board[4][3]`。

### 验收

`verify_gmk.js`：双入口 × 两种模式（主菜单纯玩 / 游戏内棋摊）× 8 档视口
（375×812 手机、812×375 横屏、1024×640、1366×600、1366×768、1920×1080、2560×1440、900×430 极矮小窗）
共 44 项全过；宽高差恒为 0、零横向溢出、弹窗不超屏；动态 resize 到 812×375 后仍正方形；
认输→结果窗→收好不卡。动画结束后复测最终边长 158~402px，格子 11.3~28.7px，均可点。
守卫为 `tools/check-content.js` 的 `checkGomokuShape()`。
