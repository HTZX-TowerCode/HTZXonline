## 1. 加一条随机事件

文件：`js/07-data-events.js`（通用）或 `js/08-data-events-school.js`（学校专属）

```js
      {
        id: "school_new_bench",          // 唯一，别和别人重名
        w: 4,                            // 权重，越大越常出现（一般 2~8）
        slot: "weekday",                 // weekday 周中 / weekend 周末 / clubday 社团课
        season: ["秋"],                  // 可选：春 夏 秋 冬
        t: "操场边的新长椅",
        c: "操场边多了一条新长椅，漆还没干透。\n放学时你绕过去看了一眼。",
        opts: [
          {t: "坐一会儿", run: ["心态 +6", "压力 -3", "提示 风把银杏叶吹到脚边。"]},
          {t: "赶回去上晚自习", run: ["效率 +2", "记 学习 1"]}
        ]
      },
```

**三条判据，写之前想一遍**

- 学校里发生的事 → `weekday`；家里/街上 → `weekend`
- **学校对手机零容忍**，宿舍里不该出现手机（踩过坑）
- 初三已是最高年级，别写「学长」「高年级同学堵你」，或加 `maxTerm: 3`

**文本反馈**：`提示 xxx` 会进文本反馈弹窗；只写数值变化会显得"没反应"，尽量每个选项都带一句。

## 3. 加一道题

文件：`js/05d-data-quiz.js` → `QUIZ_BANK[科目]`

```js
        {g: 0, type: "choice", q: "「但愿人长久」的下一句是：",
         opts: ["千里共婵娟", "把酒问青天", "此事古难全", "低绮户"],
```

|---|---|

## 模板 12 · 文具联动事件（v1.4 D）

事件里想让文具**真的**变化，就在 `run` 里写「文具」指令。别只写文案 —— 需求 15 要的是状态同步。

```js
{
  id: "my_pen_lost", w: 5, dist: "uniform", minGap: 10, slot: "weekday",
  cond: S => bagItems("write").length > 0,
  t: "笔不见了",
  c: "自习课低头要写，手伸进笔袋摸了个空。",
  opts: [
    {t: "把书包倒出来找一遍", stam: 3,
     run: ["文具 丢失 书写", "压力 +3", "提示 笔是真的没了。!bad"]},
    {t: "算了，先借支笔", stam: 1,
     run: ["文具 丢失 书写", "社交 +3"]}
  ]
}
```

可用指令（都定义在 `js/05i-data-stationery.js` 的 `stationeryCmd()`）：

| 指令 | 效果 |
|---|---|
| `文具 丢失 书写` / `球拍` / `实验` / `装饰` / `橡皮` / `任意` | 真的拿走一件 |
| `文具 磨损 书写 5` | 扣 5 点耐久，归零报废 |
| `文具 获得 gel_pen` | 获得一件（id 必须在文具表/书目表里） |
| `文具 借书 3周` | 随机借一本，第 N 周自动归还 |
| `文具 借出 3周` | 把自己的书借出去，到期回来 |
| `文具 换袋` | 给一只新布袋，解除散落 |
| `文具 散落` | 直接进入散落状态 |

**注意**：事件给的文具不受容量限制（`force`），玩家花钱买才受容量限制。散落状态下「笔不见了」这类事件权重会 +0.18。

## 模板 13 · 让天赋影响事件（v1.5 B）

事件数据里直接写字段，不用改引擎、不用写 `cond` 函数。

```js
{
  id: "my_contest", w: 4, slot: "weekday",
  talentBoost: {"逻辑鬼才": 1.8, "数学脑": 1.5},   // 有天赋更容易抽到（不屏蔽）
  t: "竞赛班选拔",
  c: "通知贴在楼梯口。",
  opts: [{t: "去试试", run: ["悟性 +6", "计数 竞赛"]}]
}
```

| 字段 | 写法 | 效果 |
|---|---|---|
| `needTalent` | `"晨型人"` 或 `["晨型人","操场晨光"]` | 有任意一个才出现（**硬开关**） |
| `needTalentAny: false` | 配合上面 | 改成「全部都要」 |
| `noTalent` | `["社恐","高冷"]` | 有任意一个就绝不出现 |
| `talentBoost` | `{"过目不忘":1.7}` | 有天赋时权重 ×1.7，**没天赋也照样能抽到** |

**什么时候用哪个**（很重要）：

- **成就计数的唯一来源**（竞赛选拔、图书角、志愿服务、深夜台灯）→ **只能用 `talentBoost`**。
  挂 `needTalent` 会让没天赋的玩家永远拿不到成就，D 批已经踩过一次。
- 人设上根本说不通的场景（晨型人在深夜台灯刷题、钢筋铁骨扭伤脚踝、自律机器被手机诱惑）→ 用 `noTalent`。
- 「一个人默默干完值日」这类小众性格场景 → 用 `needTalent`，池子少几条不影响进度。

`needTalent` / `noTalent` 对**运动事件池**（`SPORT_EVENTS`）同样生效，因为 `pickSportEvent()` 也走 `eventAllowed()`。

## 模板 14 · 精确操作某一件文具（v1.5 B）

旧的「文具 丢失 书写」是**随机挑一件**，写不出「那支钢笔断了」。现在可以直接点名：

```js
{
  id: "my_pen_break", w: 5, minGap: 12, slot: "weekday",
  cond: S => bagHas("fountain"),        // 没有这支笔就不抽
  t: "钢笔漏墨了",
  c: "笔帽里全是墨。",
  opts: [
    {t: "擦干净接着用", run: ["文具 消耗 fountain 6", "压力 +2"]},
    {t: "换回碳素笔",   run: ["文具 移除 fountain", "文具 获得 gel_pen", "心态 -2"]}
  ]
}
```

| 指令 | 效果 |
|---|---|
| `文具 消耗 fountain 6` | 那件扣 6 点耐久，归零自动报废并提示 |
| `文具 移除 gel_pen` | 直接拿走一件（不问耐久） |
| `文具 修复 bag_tin 40` | 加耐久，不超过上限 |
| `文具 获得 gel_pen 3件` | 一次给 3 件 |
| `文具 补齐 书写` | 没可用笔时补铅笔头 + 橡皮（**防死锁**） |
| `文具 归还` | 把借来的书全还回去，袋里真的少一本 |
| `bagHas("pingpong")` | 写 `cond` 用：袋里有没有这件 |

id 都在 `js/05i-data-stationery.js` 的 `STATIONERY_DEFS` / `BOOK_DEFS` 里。
写错 id 时 `tools/check-content.js` 会报中文提示；游戏里也不会崩，只给一句「袋里没有…」。

**★ 从指令里读出来的数字必须先 `parseInt`**（坑 69）：正则捕获的是字符串，

## 模板 15 · 写一条长链事件（v1.5 C）

长链 = 一条事件选完 `next` 排队弹下一条，最多 **6 层**（`GAME_CONFIG.epicMaxDepth`）。
只有**第 1 层**进随机池，后续层 `w: 0` 且 `epic: true`。

```js
{
  id: "my_epic_1", w: 4, once: true, slot: "weekday",
  t: "一张没交的报名表", c: "通知贴在楼梯口，表在讲台角上放了一叠。",
  opts: [
    {t: "填了交上去", next: "my_epic_2a", run: ["效率 +3"]},
    {t: "先放抽屉",   next: "my_epic_2b", run: ["心态 +2"]},
    {t: "不交了",               run: ["心态 +3"]}   // 没有 next = 就地收束
  ]
},
{
  id: "my_epic_2a", w: 0, epic: true, slot: "weekday",
  t: "名单贴出来了", c: "公示栏前围了一圈人。",
  opts: [
    {t: "去问老师", next: ["my_epic_3a", "my_epic_3b"], run: ["社交 +4"]},
    {t: "自己找书", next: "my_epic_3b",                 run: ["悟性 +5"]}
  ]
}
```

| 规则 | 原因 |
|---|---|
| 第 1 层 `w > 0` 且 `once: true` | 一局只开一次头，别反复起链 |
| 后续层 `w: 0` | 不走随机池，只能由 `next` 排队弹出 |
| **后续层不要写 `cond`** | 排队分支不跑 `eventAllowed()`，但会检查 `q.cond`；条件一旦不满足，**链会无声断掉**（坑 73） |
| `next` 可写字符串或数组 | 数组 = 一层里连着排两段（坑 74） |
| 不同选项指向不同收束 / 中途汇合 | 别一条线走到底；有的选项干脆不写 `next` |
| 层间 id 不许重复 | 同一条链里靠 id 区分层 |

排队后续**不占** `maxEventsPerWeek` 的随机事件配额，但有独立的 6 层深度上限；
链一断（队列空）深度立刻归零。玩家在链中途点「进入下一周」，`startWeek()` 会清掉队列，
剧情不会串到下一周 —— 所以一条链要设计成**一周内能走完**。

现有 5 条主线在 `js/05m-data-events-extra.js` 的 `EPIC_EVENTS`：
报名表（6 层）、山顶那封信（5 层）、旧楼的电闸（6 层）、校刊约稿（5 层）、操场边那棵树（4 层）。

**持续状态下**：每周心态 −9、压力 +5、效率 −2，学习收益 ×0.70；
第 3 周暂时放下一个心态 / 学习类天赋，**弹窗说明丢了什么、怎么找回**；
收心后第 4 周自动归还，也会弹一次窗。

**★ 最重要的口径（Q6①A）**：可以谈，但游戏不鼓励，且
**新手介绍 / 更新日志 / 鸣谢 / 主菜单 / 成就 / 天赋说明 / 消息栏一律不出现相关字眼**。
- 成就叫「一张纸条」，描述「递出去又收回来的那张」
- 天赋叫「心里住了一个人」，desc 只写「心态起伏变大，社交事件更常出现」
- **事件文案照常写**（课桌里的纸条、绕远的那条路），玩家自己看得懂
- 游戏内即时弹窗属于「反馈」不是「介绍」，会写清丢了什么、怎么找回

`tools/check-content.js` 的 `checkCBatch()` 会扫上面那些静态文件，出现禁词直接报错。
状态在 `S.romance`，存档 v10 迁移；相关实现全在 `js/05o-data-romance.js`。

## 模板 17 · 写事件文案：别在段尾加总结（v1.5 D）

一个选项的回话，**写完具体动作就停**。第三句往往是 AI 味最重的地方。

| 别这样 | 这样 |
|---|---|
| 你数了数还剩几站。每一步都算数。 | 你数了数还剩几站，转身回了教室。 |
| 你的被子是全场最方正的那个。一床一被，立身之始。 | 你的被子是全场最方正的那个，生活老师拿卷尺量了两遍。 |
| 你没喊出声，但每一句都听进去了。 | 你没喊出声，站在队伍里听完了。 |
| 不是你突然爱上了学习，而是你终于不再害怕它。 | 收拾书包时才发觉，坐下来这件事没费什么劲。 |

**要避开的句式**：`不是…而是…`、`原来…`、`有些…才…`、`这中间的差别，叫作…`、
`也是一种能力 / 选择 / 能量`、`未来可期`、`刚刚启航`、`这本身就很了不起`、
`阴影总会散去`、`每一步都算数`、排比三连、`——` 后面接一句升华。

**可以留**：具体动作、听到的原话、天气和物件、时间推移、有画面的短句、
破茧 / 结局自带的那句 `poem` 古诗。

`tools/check-content.js` 的 `checkDBatch()` 会扫
`08-data-events-school.js` / `12-data-cures.js` / `11-data-endings.js` / `docs/guide.md`，
出现上面这些套话直接报错。**题库题干不在这个范围**（学科原文里有「意味着：」是正常表述）。

## 模板 18 · 真实度下的数值显示（v1.5 D）

改动玩家能看见的数字时，先确认你在哪个出口：

| 出口 | 文件 | 规则 |

## 模板 19 · 图书与文具袋的三条规矩（v1.5.1）

写事件、加书、改购买逻辑时别踩：

1. **只有笔（write）和橡皮（eraser）占格子**（v1.5.3 收紧，早期版本是「书不占格子」）。
   容量一律用 `bagCount()`，不要写 `S.bag.items.length`。
   `bagEnsure()` 里是「先分 `occupying` / `free` 两拨，只有 `occupying` 才 `slice(0, cap)`」，
   顺序反了书和球拍会被切掉。
2. **一个存档里一种书同时只有一本**。`bagHasBook(defId)` 连 `S.bag.lent`（借出去的）一起看，
   `bagAdd()` 会自动拒重并给一句中文提示。事件里写「文具 获得 bk_xxx」不用自己判重，
   但**别在文案里承诺一定拿到**，最好写成「同学递来一本书」这种可进可退的说法。
3. **读完的书留在书架，可复读**。`it.finished` 为真时 `bookRead()` 自动转 `bookReread()`，
   不推进进度、不抽天赋，只给 `BOOK_REREAD` 里的一点余味。加复读效果改 `BOOK_REREAD` 数组即可。

`bagIsBook()` / `bagCount()` / `bagBooks()` / `bagHasBook()` **都不调 `bagEnsure()`**，
调用前自己先 `bagEnsure()`，否则会递归。

`bagBuy()` 是**先放货再扣钱** —— 别改回「先扣钱」，买重被拒时会白吞玩家的钱。

## 模板 20 · 加一道题（v1.5.2）

题库现在分三批，依次 `push` 进同一个 `QUIZ_BANK`：

| 文件 | 表 | 说明 |
|---|---|---|
| `js/05d-data-quiz.js` | `QUIZ_BANK` | 主表，同学的老习惯 |
| 同上 | `QUIZ_EXTRA` | 第一批追加 |
| `js/05d2-data-quiz-more.js` | `QUIZ_MORE` | **新题加这里**，文件头有完整的年级约束说明 |

两种格式，和主表完全一样：

```js
{g: 0, type: "choice", q: "《春》的作者是：", opts: ["朱自清", "老舍", "鲁迅", "冰心"], ans: "朱自清", why: "朱自清《春》"},
{g: 1, type: "fill",   q: "补全：感时花溅泪，______。", ans: "恨别鸟惊心", why: "杜甫《春望》"},
```

**四条硬规矩**（体检脚本会查，写错会报错或变成永远抽不到的死题）：

1. `g` 是**最低年级**：`0` 初一、`1` 初二、`2` 初三。
2. 科目开课年级要对得上：
   - 语数英 / 历史 / 政治 → `g` 0、1、2 都行
   - **物理** 只能 1 或 2，**化学** 只能 2（初一没这两门课）
   - **生物 / 地理** 只能 0 或 1（初二下生地会考后锁死，初三不再考）
3. 选择题的 `ans` 必须**原样出现在 `opts` 里**，否则玩家永远答不对。
4. 填空题答案写**唯一短词或数字**，别写"也叫××""可写××"这类多解词。
   `quizMatch()` 已经很宽容（一/1/1.0、1/2/0.5/二分之一、书名号、单位都认），但它变不出第二种说法。

**别和已有 265 道题干撞车** —— 体检脚本新增了重复题干检查（同一题干配两个不同答案是内容事故，会直接报错）。

改完跑：

```
cd tools
node check-content.js
```

会打印「共载入 493 道题目」和三个年级各自可抽数；低于 450 道、或某个「年级 × 科目」不足 15 道，都会提示。

## 模板 21 · 加一件文具 / 改货架分组（v1.5.3）

**加文具**：往 `js/05i-data-stationery.js` 的 `STATIONERY_DEFS` 加一条，会自动出现在小卖铺对应分组里，**不用改任何别的文件**。

```js
{id:"compass", n:"圆规", icon:"📐", cat:"lab", dur:50, price:18, weekly:1, desc:"画圆时手别抖。"},
```

字段和几条硬规矩：

| 字段 | 含义 |
|---|---|
| `id` | 全局唯一，事件指令 `文具 消耗 compass 3` 靠它点名 |
| `n` | **纯文字名字，不要带 emoji**。面板已经单独画一个 `.bag-ico`，名字里再写 ✏️ 会显示两个图标 |
| `icon` | 一个 emoji，单独显示 |
| `cat` | `write` / `eraser` / `bag` / `sport` / `lab` / `charm` / `book` |
| `dur` | 耐久；`999` 表示常新（装饰小物） |
| `price` | 小卖铺固定价 |
| `weekly` | 每周折算给最弱科的学习数值（可选） |
| `perk` | 每周给的属性收益（可选，如 `{"心态":2}`） |
| `need` | `"eraser"` 表示这支笔必须同时有橡皮才能用（铅笔类） |
| `cap` | **只有 `cat:"bag"` 用**，决定笔袋能装几支笔 |

**只有 `cat:"write"` 和 `cat:"eraser"` 占格子**。其余文具、文具袋本身、书全部不占，放在书包 / 课桌 / 书架上。

因为不占格子，耐用品加了防囤规则：`sport` / `lab` / `charm` **同类只留一件**（`bagHasDurable()`），
`bagWeeklyTick()` 也按 `def` 去重算 `weekly` / `perk` —— 买十个计算器不会每周白刷学力。
事件用 `force:true` 发奖励不受这个限制。

**改货架分组**：改 `SHOP_GROUPS` 数组，一项一组。`cat:"book"` 那组会自动列全部 `BOOK_DEFS`。
分组标题和提示（`hint`）随意写；新增分组记得体检脚本会检查「每组至少有一件商品」。

**加书**：往 `BOOK_DEFS` 加一条，格式见模板 14；新书会自动进「📚 书」组、图书角和周末网购池。
`stages` 里的 `at` 要递增、最后一条必须是 `1`，效果用中文指令（`心态 +4` / `学力 语文 +20`）。

改完跑 `cd tools && node check-content.js`，会打印「40 种文具 + 16 本书 · 7 组全量陈列 · 图标不重复」。
